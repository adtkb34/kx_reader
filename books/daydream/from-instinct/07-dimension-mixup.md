title: 维度错位
---
同级节点本该落在**同一把尺子**上。尺子没定，或同级已经混进多种尺子，就是维度错位——与同维里谁深谁浅无关。

上一章 [坐标约定](06-shared-frame.md#claim) 谈的是：先显式共用一套框架；本章谈框架内部最常见的破法——**同级混轴**。

## 主张 {#claim}

**维度错位**：用来排同级的抽象维度未选定，或未守住，以致不同切法上的节点被当成一类并列。  

它回答的是「这一层在用哪把尺子量」；不回答「同一把尺子上谁包含谁」。后者是 [层级错位](08-hierarchy-mixup.md#claim)。

## 同级在要求什么 {#what-peers-require}

「同级」成立，前提是兄弟节点可用**同一句式**概括，且落在同一抽象维度上。常见尺子彼此不同：

| 切法 | 在量什么 |
| --- | --- |
| 对象 / 实体 | 人、店、单、设备 |
| 能力 / 职能 | 认证、经营、履约、质控 |
| 任务 / 路径 | 如何进场、如何办成一件事 |
| 模块 / 组件 | 可复用的服务或子系统 |

概括失败，优先怀疑**维度混了**，不要先去调标题深浅——深浅是同维问题。

## 为何会混 {#why}

1. **未显式选轴**：动手前列了一堆「都要出现的词」，词来自多种切法，直接排成同级。与 [完整感陷阱](04-completeness-trap.md#claim) 同构：先齐，后对。也等于跳过了 [坐标约定](06-shared-frame.md#claim)。  
2. **用途与切法绑死却未声明**：同一批内容，按「使用路径」与按「实现模块」是两套合法同级，混用不声明，同级必然打架。  
3. **一棵树伺候多种找法**：现实是网，多种切法可并存；一份目录 / 菜单一次只能认一种主轴。其余关系应链接或另树，不该挤进同一层兄弟。

## 例子 {#examples}

下面比的是**尺子**，不是嵌套深浅：

:::details 写需求 / 章节同级
「账号登录」与「商铺管理」并列：一个像任务入口，一个像业务对象域——句式概括不起，是维度混杂。  
（若已统一为业务域，却把「编辑商铺资料」抬到与「售后」同级，那是层级问题，见 [层级错位](08-hierarchy-mixup.md#claim)。）
:::

:::details 产品导航
「搜索」「我的订单」「帮助中心」「品牌故事」同级：工具、对象集合、内容栏目混坐一排。乱的是分类轴，不是某个栏目少缩进了一级。
:::

:::details 组织
业务结果线与专业标准线两把尺子并存时，「他该和谁算一类」会永远吵。争的是主轴，不是汇报层级画深一点就能消掉。
:::

:::details 收藏与分类
按项目、按主题、按来源、按紧急度都是合法切法。一套同级想同时满足四种，兄弟会不断增生、拆并——缺的是「这一次只用哪把」，不是缺文件夹深度。
:::

## 对策 {#rule}

先写下**这一次同级只用的尺子**，只允许一种：

- 同级节点都按这把尺子命名与归类；概括不成同一句式 → 先换轴或拆出，不先调缩进。  
- 其它真实关系用链接、标签、另一棵树表达，不塞进当前同级。  
- 用途一变，允许换轴；不要幻想一层兄弟伺候所有切法。

尺子守住之后，若仍觉得「该挂下的没挂下」，再按 [层级错位](08-hierarchy-mixup.md#rule) 看同维嵌套。

## 收束 {#close}

维度错位是**同级坐标系的问题**：这一层在量什么，有没有混进别的量法。  
先定并守住尺子；不要把「轴没选对」当成「标题层级没调好」来改。
