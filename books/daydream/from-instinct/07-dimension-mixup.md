## 主张 {#claim}

**维度错位**：用来排同级的抽象维度未选定或未守住，不同切法上的节点被当成一类并列。它管「这一层用哪把尺子」；「谁包含谁」见 [层级错位](08-hierarchy-mixup.md#claim)。先有共用切法，见 [坐标约定](06-shared-frame.md#claim)。

## 同级在要求什么 {#what-peers-require}

兄弟节点须能用**同一句式**概括，且落在同一抽象维度。常见尺子彼此不同：

| 切法 | 在量什么 |
| --- | --- |
| 对象 / 实体 | 人、店、单、设备 |
| 能力 / 职能 | 认证、经营、履约、质控 |
| 任务 / 路径 | 如何进场、如何办成一件事 |
| 模块 / 组件 | 可复用的服务或子系统 |

概括失败，优先怀疑维度混了，不要先调标题深浅。

## 为何会混 {#why}

1. **未显式选轴**：先堆「都要出现的词」，词来自多种切法却排成同级——不立薄架就堆料，见 [框架先行](10-framework-first.md#20260729191401)。  
2. **用途与切法绑死却未声明**：按路径与按模块是两套合法同级，混用不声明必打架。  
3. **一棵树伺候多种找法**：一份目录一次只认一种主轴；其余用链接或另树，不挤进同一层兄弟。

## 例子 {#examples}

:::details 写需求 / 章节同级
「账号登录」与「商铺管理」并列：任务入口与业务对象域混坐。  
（若已统一为业务域，却把「编辑商铺资料」抬到与「售后」同级 → [层级错位](08-hierarchy-mixup.md#claim)。）
:::

:::details 产品导航
「搜索」「我的订单」「帮助中心」「品牌故事」同级：工具、对象集合、内容栏目混尺。
:::

:::details 组织
业务结果线与专业标准线并存时，「他该和谁算一类」争的是主轴，不是汇报层级画深一点。
:::

:::details 收藏与分类
按项目 / 主题 / 来源 / 紧急度都合法；一套同级想同时满足四种，缺的是「这一次只用哪把」。
:::

## 对策 {#rule}

写下**这一次同级只用的尺子**，只允许一种。其它关系用链接、标签、另一棵树。用途变了允许换轴。尺子守住后若仍「该挂下的没挂下」，再看 [层级错位](08-hierarchy-mixup.md#rule)。
