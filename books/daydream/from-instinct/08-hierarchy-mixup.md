{#claim}
## 主张

**层级错位**发生在**同一维度内部**：父子该怎么嵌套没分清——谁包含谁、谁更粗。若同级其实不在同一把尺子上，先去 [维度错位](07-dimension-mixup.md#claim)。

{#what-level-means}
## 同维里父子在量什么

上级通常更粗；下级更细、被包含或被展开：

| 维度     | 粗 → 细（示意）            |
| -------- | -------------------------- |
| 地理     | 省 → 市 → 区               |
| 业务对象 | 商铺 → 商品 → SKU          |
| 任务路径 | 进店购物 → 结算 → 确认支付 |
| 文档结构 | 章 → 节 → 条               |

常见两种：

1. **该嵌套却并列**（含**缺父抬级**：父未写出，子项被抬到与粗项兄弟同级）
2. **该并列却嵌套**：同粒度硬塞进父子

{#why}
## 为何会分不清

1. **包含关系被名字盖住**：两个词都像「一块功能」，看不出展开关系。
2. **缺架堆词**：先列都要出现的词再补嵌套——不立薄架就堆料，见 [框架先行](10-framework-first.md#20260729191401)。
3. **和维度问题叠在一起**：尺子未定时装成层级之争；坐标是否约定过，见 [坐标约定](06-shared-frame.md#claim)。

{#examples}
## 例子

假定**已经在同一把尺子上**：

:::details 大纲 / 章节
「订单详情」「订单状态」与「售后」并列：前两项应挂在「订单」下。  
「支付」与「点击确认支付」并列：同路径，粒度差一截。
:::

:::details 导航 / 菜单
「商铺管理」与「编辑商铺资料」同级：后者是前者下的动作或子页。
:::

:::details 地理与组织（同轴）
「华东」与「上海」并列；或把两个同级事业部做成上下级。
:::

:::details 知识分类
「动物」与「猫」同级；或「项目 A」「项目 B」被塞进彼此之下。
:::

{#rule}
## 对策

先确认同一维度，再只问嵌套：同级是否同粒度？细项是否共用未写出的父？A 是否被 B 包含/展开？调层级时只动深浅，不顺便换尺子。
