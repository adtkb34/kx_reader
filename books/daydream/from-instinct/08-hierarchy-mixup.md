title: 层级错位
---
尺子已经选定，内容也落在同一维度上——仍可能排错：该上下级的排成了同级，或反过来。

## 主张 {#claim}

**层级错位**发生在**同一维度内部**：父子该怎么嵌套没分清。  
不是「用了哪把尺子」的问题，而是「这把尺子上，谁包含谁、谁比谁更粗」没排对。  
若同级节点其实不在同一把尺子上，那是 [维度错位](07-dimension-mixup.md#claim)，先换章。

## 同维里父子在量什么 {#what-level-means}

同一维度上，上级通常更粗、更概括；下级更细、被包含或被展开。例如：

| 维度 | 粗 → 细（示意） |
| --- | --- |
| 地理 | 省 → 市 → 区 |
| 业务对象 | 商铺 → 商品 → SKU |
| 任务路径 | 进店购物 → 结算 → 确认支付 |
| 文档结构 | 章 → 节 → 条 |

错位常见两种：

1. **该嵌套却并列**：细项与粗项甩成兄弟。常见样子是**缺父抬级**——父节点没写出来，子项被抬到与真正的兄弟粗项同级。  
2. **该并列却嵌套**：本是同粒度的几块，硬塞进父子，树被拉歪。

示意（同维；第 1 种里的缺父抬级）：

```
当前                应该
a1                  A
a2                    a1
B                     a2
                    B
```

`a1`、`a2` 与 `B` 粒度不同；缺了父节点 `A` 之后，细项浮上来和 `B` 抢同级。尺子没换，是包含与深浅排错了。

## 为何会分不清 {#why}

同一维度上仍会乱，常见原因：

1. **粒度漂移**：同级混进了粗细不同的项——包括心里有父节点 `A`、落笔却只写出 `a1`、`a2`，细项被抬到与 `B` 同级（缺父抬级就是这种漂移落在树上的样子）。  
2. **包含关系被名字盖住**：两个词都像「一块功能」，看不出一个是另一个的展开。  
3. **完整感抢跑**：先列出都要出现的词，再补嵌套——与 [完整感陷阱](04-completeness-trap.md#claim) 同构：先齐，后对。  
4. **和维度问题叠在一起**：尺子未定时装成「层级之争」，越调越乱；先交给 [维度错位](07-dimension-mixup.md#claim)。坐标是否约定过，见 [坐标约定](06-shared-frame.md#claim)。

## 例子 {#examples}

概念本身不绑在某一行当。下面都假定**已经在同一把尺子上**：

:::details 大纲 / 章节
「订单详情」「订单状态」与「售后」并列：前两项本应挂在「订单」下，与「售后」平级的是「订单」整枝，不是详情本身。  
「支付」与「点击确认支付」并列：同属任务路径，粒度差了一截。
:::

:::details 导航 / 菜单
「商铺管理」与「编辑商铺资料」同级：后者是前者下的动作或子页。  
用户找得到入口，却不断在「同级里再找一层」——树深画错了，不是缺入口。
:::

:::details 地理与组织（同轴）
「华东」与「上海」并列当同级区划；或把两个同级事业部做成上下级。  
轴是地理或汇报线，错的是包含与平级，不是轴本身选错。
:::

:::details 知识分类
「动物」与「猫」同级；或「项目 A」「项目 B」被塞进彼此之下。  
主题轴没混，粗细与包含乱了。
:::

## 对策 {#rule}

先确认当前排的是**同一维度**（否则先去处理维度错位）。然后只问嵌套：

- 同级是否**同粒度**？能否用同一句式概括，且抽象高度接近？  
- 若干细项是否其实共用一个未写出的父节点？是 → 补父、降子，再与真正的粗项兄弟并列。  
- A 是否**被 B 包含 / 展开**？是 → 不该并列。  
- 调层级时只动深浅，不顺便换尺子；换尺子是另一件事。

## 收束 {#close}

层级错位是**同维上的父子之乱**：该深的浅了，该平的叠了，或缺了父节点把细项抬了级。  
先分清是不是同一维度；是，再排粗细与包含。把「尺子没定」误诊成「标题层级」，会越改越像在排版，却总排不对。
