{#claim}
## 主张

多人了解同一事务时，优先**约定一套共用坐标**：一事可生出许多维度，从中选出若干维作**尺子**——尺子是不同人共用的基准；再让各角色在同一坐标上看自己相关的切片。  
坐标是契约，不是事务自带的唯一真相——换用途、换人群，允许换轴、换尺。

{#object-frame-slice}
## 对象、维度、尺子、切片

| 词 | 指什么 |
| --- | --- |
| 对象 | 大家大致在谈同一件事 |
| 维度 | 这件事上可切开的抽象轴（可很多） |
| 尺子 | 从中选出、用作共用基准的那几维（或那一维） |
| 切片 | 某人真正深挖的那一枝或那几维 |

有共同对象 ≠ 已选共用尺子。有共用尺子 ≠ 每人走完所有枝。

同级怎么守尺，见 [同级同尺](07-dimension-mixup.md#claim)；同尺上粗细怎么挂，见 [同维嵌套](08-hierarchy-mixup.md#claim)。

{#limits}
## 限度

1. 主尺对某角色处处别扭、只能靠心智换算 → 换尺，或加第二视图（标签、矩阵、另树）。  
2. 强行「万事只有这一套」会把未选维伪装成已共用尺子，同级就守不住。  
3. 一份主目录 + 若干旁路找法，往往比幻想一棵树伺候所有人更诚实。

{#examples}
## 例子

:::details 软件协作
团队约定「先按模块挂，再挂具体项」。测试也可先选模块再落到用例——与开发同图，切片不同。按关键路径 / 风险先切往往也成立。
:::

:::details 需求与实现
产品按用户任务讲，研发按服务边界讲。从不声明两套坐标如何对照，评审会各执一图。
:::

:::details 组织对齐
业务线与专业线都能描述同一个人的工作。共用哪张汇报图是契约；另一维用虚线、矩阵或双线汇报补。
:::
