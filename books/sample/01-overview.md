这是**文档书阅读器**的说明书，也是写其它书时的规范入口。顶栏可切换 **场景**（用法与判断）与 **实现**（格式合同与设计）。生成其它书前，请读完「写作」域，并在实现透镜下核对自检清单。

{#problem}
## 要解决的问题

让人能**系统审读**长篇项目文档（尤其是 AI 反复生成/重写的），并且**审读状态与备注在内容重写后仍然还在**。

它不替代普通「发布站」。发布站解决「给人看」；这里解决「给人审」。

痛点分三层：

1. **读不动** — 细节写全抓不住主干；只写主干又无处核对细节。
2. **审不清** — 不知道看到哪、哪里存疑、哪里已确认。
3. **留不住** — 内容一重写，批注要么丢、要么和正文缠在一起被覆盖。

:::details 为什么不用现成的文档站点
- 没有小节级「未读 / 已读 / 疑问 / 确认」；
- 备注需要与内容分离，重写后不能丢；
- 需要稳定小节地址，并与阅读器配套；
- 通常不做按小节对齐的版本对比，也缺少可读类型切换。
:::

{#approach}
## 方案要点

| 机制 | 作用 |
| --- | --- |
| 稳定小节地址 | 审读对象有永久位置 |
| 标注与内容分开存放 | 重写内容不擦掉审读产物 |
| 失联标注可找回 | 地址消失时不静默丢失 |
| 主干 + 可展开细节 | 先判断、再下钻 |
| 书形态与双透镜 | 降低切换成本：场景看用法，实现看规范与设计 |

一句话：**文档按可审读的地址来组织；阅读器按降低切换成本来呈现；标注按与内容解耦来保存。**
