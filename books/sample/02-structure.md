写书先定结构，再填内容。本页是组织原则；机械格式在实现透镜的 [内容格式规范](03-format.md#layout)（可顶栏切换）。

## 三条原则 {#thesis}

**总分总 + 垂直内容拆分 + 统一维度嵌套。**  
目标同一：降低上下文切换，让审读能连续推进。

## 总分总 {#general-specific}

每一层都先给判断，再下钻，再收束；禁止把叶子细节抬到「总」层。

| 层级 | 「总」 | 「分」 | 「总」（收束） |
| --- | --- | --- | --- |
| 全书 | 概览：问题 / 方案 / 地图 | 垂直域 | 自检页 |
| 域 | 本域负责什么 | 域内各页 | 清单或回链 |
| 页 | 页首导语 | 同维度小节 | 细节进 details |
| 小节 | 一句话结论 | 论据 / 步骤 | 边界进折叠 |

检验：读者**不展开任何 details、不点进子页**，仍能在该层做出整体判断。

## 垂直内容拆分 {#vertical-split}

按读者要完成的**连续心智任务**拆域，不要按「先所有概述、再所有细节」切。

本书四域：

1. **写作** — 内容怎么生成才可审、可活
2. **阅读** — 怎么在书形态里扫读与定位
3. **审读** — 状态 / 备注 / 对比等「读的产出」
4. **系统** — 为何标注能存活、架构边界

跨域只用链接；不要把另一域的主干塞进本页当同级标题。

## 统一维度嵌套 {#uniform-dimension}

同一父节点下的兄弟节点，必须属于**同一抽象维度**。换维度只能通过：换页 / 换 group、降级进可展开细节、或顶栏透镜（见 [阅读透镜](06-lenses.md#why)）。

- 一页只服务一个主问题；第二主问题 → 拆页
- h2 清单应能用同一句式概括（皆为「步骤」、皆为「组件」……）；概括失败 = 维度混杂
- `_intro` 只做本页导语，不承担另一垂直域的正文
- group 是域标签，不是可翻页总论页

**反例**：旧版概览把「解决问题」「如何阅读」「系统架构」做成同级 h2——分别是动机 / 操作 / 实现。  
**正例**：概览只保留「全书地图」维度；操作进阅读域；架构进系统域。

## 为什么这样写 {#why-it-works}

```text
人的注意力成本 ≈ 上下文切换次数 × 每层信息密度
```

- 总分总 → 控制密度：先给可决策的粗粒度
- 垂直拆分 → 减少任务切换：同一时段只待在一个域
- 统一维度 → 减少概念切换：同级标题共享抽象
- 稳定 id + 标注外置 → 「读」变成可累积的「审」

## 写前结构自检 {#checklist-structure}

- [ ] 全书有没有一张「总」地图页？各垂直域边界是否清楚？
- [ ] 每一页的同级 h2 能否用同一句式概括？
- [ ] 细节是否都进了 details，主干能否单独做判断？
- [ ] 跨域内容是否只通过链接引用、没有硬塞同级标题？
