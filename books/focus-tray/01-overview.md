脑子里同时记「要做的事」和「正在做的事」，注意力会被占满。Focus Tray 把事先收到一个地方，再按 GTD 的节奏理清楚，最后按情境推进——不是又一个待办清单，是一套**从收到手、再到做完**的台子。

这本书是**测试样例**：场景与约束已经挂上；用 `kx lint` / `kx build` 追问空洞，再交给别的 AI 去实现。约束怎么写见 [规范记法](../sample/13-spec-notation.md#202608020101)。

## 五步怎么落成模块 {#202608022101}

| GTD 步骤 | 本书模块 | 人在干什么 |
| --- | --- | --- |
| 收集 Capture | [收集箱](capture/01-inbox.md#202608022111) | 随手扔进来，不判断 |
| 澄清 Clarify | [澄清](clarify/01-process.md#202608022121) | 逐条问：是不是事、两分钟、委派、延期 |
| 组织 Organize | [项目](organize/01-projects.md#202608022131)、[情境](organize/02-contexts.md#202608022141) | 挂到项目或清单，标情境 |
| 回顾 Review | [每周回顾](review/01-weekly.md#202608022151) | 扫一遍系统是否可信 |
| 执行 Engage | 各清单上的「下一步」 | 按情境选一件做 |

执行不单独开一章：它就是组织好的清单在被用。

## 边界 {#202608022102}

这一版只解决「一个人把事理清楚，偶尔把一个项目露给同事看」。

| 做 | 不做 |
| --- | --- |
| 收集箱、项目、下一步、等待、日程 | 番茄钟、习惯打卡、专注统计 |
| 情境过滤（@电脑、@电话…） | 复杂权限、多租户企业版 |
| 每周回顾清单 | 自动智能排程、AI 替你澄清 |
| 单人为主，项目可只读共享 | 实时协同编辑、评论流 |

右列不是永远不做，是这一版不做。凡是这一版不做的，都不要在规范表里留半截字段。
