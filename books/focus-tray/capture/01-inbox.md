title: 收集箱
---
收集箱是唯一允许「不思考」的入口。事一冒出来就丢进来，判断留给澄清——否则人会在入口处卡住，最后什么都不记。

## 谁在用 {#202608022111}

| 角色 | 典型一刻 |
| --- | --- |
| 自己 | 开会听到一句「下周把报价发我」，随手记一条，不开项目 |
| 自己 | 走路想到「该约牙医了」，语音或快捷键丢进箱 |
| 自己（晚些时候） | 打开箱，准备开始澄清 |

别人不能往你的收集箱里扔东西——这一版没有「代记」。共享发生在项目层，见 [项目](../organize/01-projects.md#202608022131)。

## 场景 {#202608022112}

### 快速捕获

人在别的事中间，留给收集箱的时间往往只有几秒。入口要短：一句话正文就够，标题可自动截前几字。成功的标准是**丢完还能立刻回到刚才在做的事**，不是把这条整理漂亮。

### 从邮件 / 聊天粘过来

整段粘贴也算一条。人不应被强迫先拆成多条——拆是澄清时的事。箱里允许又长又脏的原文。

### 箱满了也不催

收集箱可以堆着。系统不弹「你有 47 条未处理」逼人立刻澄清；压力来自人自己选的回顾节奏，见 [每周回顾](../review/01-weekly.md#202608022151)。

## 和别处的边界 {#202608022113}

| 看起来像 | 实际归属 |
| --- | --- |
| 「明天交报告」直接写进日程 | 仍先进收集箱；日期是澄清时标的 |
| 「买牛奶」这种琐事 | 同样进箱；澄清时可能进「下一步」或「某天」 |
| 已经想好属于哪个项目 | 仍建议先进箱再澄清——例外入口容易变成第二个脑 |

## 收集箱条目 `inbox_items` {#202608022115}

箱里只有「还没澄清」的东西。澄清走完任一出路，这一行就删掉——不留「已处理」坟场，避免和行动清单抢注意力。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| 拥有者 `owner_id` | 引用 用户 | 必填 |
| 正文 `body` | 长文本 | 必填，≤8000 |
| 来源 `source` | 文本 | 可空，≤64 |

| 可见性 | 规则 |
| --- | --- |
| 拥有者 | 拥有者本人可读写 |
| 默认 | 私有 |

澄清章的动作作用在本实体上；本表不另开状态机。
